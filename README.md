# Учёт расходов

![CI](https://github.com/oleg-belyanin/expense-tracker/actions/workflows/ci.yml/badge.svg)
![Debug APK](https://img.shields.io/github/v/release/oleg-belyanin/expense-tracker?label=debug%20apk)

Android-приложение для личных трат: куда уходят деньги по категориям и по времени,
а не только «сколько всего». Сервера нет. Данные и правила категоризации живут
на устройстве и сами никуда не уходят — наружу только если пользователь сам
экспортирует файл или шлёт копию.

## Что умеет

- Записать трату за несколько секунд: сумма, дата (по умолчанию сегодня),
название, категория, место, необязательный комментарий. Категория
подставляется сама, её можно поменять. Место и название подсказывают
недавние значения. Запись можно править и удалить с подтверждением.
- Десять бытовых категорий из коробки плюс свои. Удаление — в архив:
старые расходы не пропадают.
- Список по дням, поиск, фильтры (период, несколько категорий, место)
и сумма именно по текущему срезу.
- Аналитика за месяц / прошлый месяц / год / всё время / свой период:
две визуализации одних данных, соседние месяцы, тап по категории
открывает тот же срез в списке.
- CSV расходов и полная резервная копия JSON; повтор той же копии
историю не удваивает. Можно стереть расходы и оставить выученные правила.
- Светлая, тёмная и системная тема.

Готовый debug APK: [Releases](https://github.com/oleg-belyanin/expense-tracker/releases/latest)
(`app-debug.apk`). Сборка с нуля — в конце файла.

## Как устроено

Экраны не считают категории и не ходят в сеть. Сценарий (сохранить трату,
посчитать месяц) спрашивает хранилище и отдельный движок правил.

```text
Экраны  →  сценарии (сохранить, найти, отчёт)
              ↓                    ↓
         SQLite на телефоне    движок категорий
              ↑
         словарь при установке (не «модель с сервера»)
```

Правила — таблицы и файлы словаря, не условия в кнопках. Подробности формул —
`[docs/categorization-architecture.md](docs/categorization-architecture.md)`.

## Категоризация

Не машинное обучение и не внешний сервис. Один и тот же нормализатор текста
(регистр, пробелы, `ё`→`е`) у приложения и у генератора словаря.

**Откуда берётся категория** — в таком порядке, всегда одинаково:

1. **Исправление пользователя.** Если это название уже правили руками —
  ставится его категория. Перебивает словарь. «Латте» и «  ЛАТТЕ  » —
   одно и то же имя.
2. **Слова в названии.** «Латте» → Кафе, «Кетостерил» / «аптека» → Здоровье.
  Часть слов однозначны, часть — только намёк; движок усредняет известные слова.
3. **Место.** «Шоколадница» тянет в Кафе, «Лукойл» — в Транспорт. Если в одном
  месте покупают разное («Пятёрочка»: еда и быт), место само категорию
   не назначает: важнее название. В списке выбора такие категории всё равно
   поднимаются вверх.
4. **«Прочее»**, если ничего не сработало. Поле категории не пустое,
  ошибки нет.

Пример конфликта: таблетки в «Пятёрочке» — побеждает здоровье по названию,
а не «продукты» по магазину.

**Как запоминает правки.** Поменяли категорию — решение сохраняется для этого
имени и подставляется в следующий раз. Счётчик правил виден в настройках.
Правила переживают очистку истории и попадают в резервную копию.

Словарь при первом запуске — около тысячи размеченных примеров
(`[seed-data/](seed-data/)`), не скрытая модель. Параметры —
`[seed-data/categorization-config.json](seed-data/categorization-config.json)`.
На отложенной выборке seed v1: точное попадание **85 %**, в «Прочее» **10 %**.

Дополнительно к четырём источникам из задания (не вместо них): если название
совпало с именем категории — берём её; однозначные полные имена из словаря
идут раньше «намёков». Если места ровно 50/50 и пользователь уже явно перевёл
одну из этих категорий в другую — берём ту, куда переводил.

Пока набирают слово, подсказки из истории и словаря («Ригл» → «Ригла»).
На форме пустое поле показывает 3 недавних значения; после первой буквы — до 8.

## Категории

Десять встроенных: Продукты, Кафе, Транспорт, Здоровье, Жильё, Связь,
Развлечения, Одежда, Дом, Прочее. Состав — `[seed-data/categories.yaml](seed-data/categories.yaml)`.

Свои категории: имя, цвет, значок. Встроенные тоже можно убрать в архив,
кроме «Прочее». Расходы и правила остаются привязаны к той же категории;
в новых тратах архивная не предлагается, в истории и отчётах видна.
Повторное создание того же имени возвращает ту же категорию, не дубль.

## Решения, где задание оставляло свободу

- Валюта ₽, интерфейс на русском. Дату в будущем выбрать нельзя.
- Форма новой траты — отдельный полный экран, все поля сразу.
- Настройки — шестерёнка на любой вкладке, без четвёртого пункта внизу.
- Демо из 300 трат только в debug-сборке и только при первом запуске.
Очистка истории его снова не подкладывает.



## Стек и почему

Kotlin и Jetpack Compose — один язык от правил до экрана. Room + встроенный
SQLite с полнотекстовым поиском — данные переживают перезапуск, поиск
на тысячах записей без сервера. Навигация только у вкладок, формы и настроек;
фильтры и подтверждения — панели поверх экрана. Без Hilt/Koin: зависимости
собраны явно. Графики — Vico и Canvas. В настройках приложения хранится
только тема.

## Сборка и запуск

Нужны **JDK 17** (`JAVA_HOME` — JDK, не JRE), **Android SDK**
(Platform 37.0, Build-Tools 36.0.0, platform-tools) и Android Studio
по желанию. Gradle Wrapper уже в репозитории.

```bash
cp local.properties.example local.properties   # прописать sdk.dir
./gradlew check                                 # линтер и тесты
./gradlew :app:installDebug                     # на эмулятор или телефон
```

`local.properties` не коммитится. Debug подписывается стандартным
`~/.android/debug.keystore`. Релизный ключ и магазин не настраиваются.

Эмулятор 360×800: `[docs/emulator.md](docs/emulator.md)`.

```bash
export ANDROID_HOME=~/Android/Sdk
$ANDROID_HOME/emulator/emulator -avd ExpenseTracker_360 &
./gradlew :app:installDebug
```

Чистый клон собирается без правок исходников.

## CI и APK

Каждый push и PR: тесты, сверка словаря с генератором, debug APK.
Эмулятора в CI нет. Падение теста или lint — красный PR.

- [Releases](https://github.com/oleg-belyanin/expense-tracker/releases/latest) — актуальный `app-debug.apk`
- Actions → успешный прогон → Artifacts → `app-debug` (7 дней)

```bash
gh release download debug-apk --repo oleg-belyanin/expense-tracker --pattern '*.apk'
```



## Демо-данные

Словарь категорий и демо-список — разные вещи. Словарь не содержит сумм и дат.
Для проверки списка и аналитики debug-сборка при первом запуске импортирует
`[demo-data/expenses-ui.csv](demo-data/expenses-ui.csv)` (300 строк).
Release-APK файла не содержит.

Набор на 5 000 записей для проверки списка пишется в `demo-data/local/`
и в git не кладётся:

```bash
./gradlew :seed-generator:generateNfrDemo
```



## Экспорт, копия, очистка

CSV расходов сохраняется в Загрузки, оттуда можно поделиться штатными средствами
Android. В файле — дата, сумма, название, категория, место, комментарий.

Резервная копия — один JSON: траты, категории, места и выученные правила.
Повреждённый или чужой файл показывается понятной ошибкой, текущие данные
не трогаются. Повтор той же копии записи не дублирует.

Очистка истории удаляет траты и оставляет категории и правила. Нужно
подтверждение.

При обновлении схемы базы старые данные не стираются: неизвестная версия
останавливает запуск, а не пересоздаёт пустую базу.

## Что не вошло и что сделали бы за неделю

Не делали захват из камеры/шаринга, импорт банковской выписки и фоновую
очередь повторов. Тесты алгоритма и отчётов плюс GitHub Actions — да.

Если бы была ещё неделя: демонстрация из задания — 2–4 минуты видео или скриншоты основных сценариев на телефоне; замер холодного старта и списка из 5 000 на обычном аппарате; замер качества подстановки категорий и мест.

Дальше по продукту, уже за рамками этой сдачи:

- в настройках — опция пересчитать старые расходы, когда меняются категории
или словарь (ручной выбор пользователя не трогать);
- редактор правил: не только счётчик в настройках, а правка вклада слов
и мест — пользовательские веса в расчёте категории;
- доходы и бюджет: для учёта «куда уходят деньги» естественно видеть
ещё и «что пришло» и лимит на месяц.



## Известные ограничения

- Видео 2–4 минуты или скриншоты основных сценариев ещё не собраны.
Сейчас гоняли на эмуляторе `ExpenseTracker_360`. Два замера скорости
из задания на обычном телефоне не делали: открытие приложения ≤ 2 с
и список из 5 000 записей (прокрутка, поиск и фильтр ≤ 300 мс).
- В автоматической сборке нет эмулятора — только проверки кода и APK.
